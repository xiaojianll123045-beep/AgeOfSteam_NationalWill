# 1. 总览与设计原则

## 1.1 定位

玩家 = 国家意志。建筑与经济系统是玩家在"没有个人部队、没有个人 RPG 玩法"之后的主要经营玩法，同时为战争提供后勤与战斗力来源。

**经济服务于战争，不是第二个游戏。**

## 1.2 核心循环

```
国策解锁 → 建造（材料 + 时间）→ 产出商品 → 市场平衡（价格 / 收入 / 军需）
      ↑                                                        ↓
      └──────────── 税收 / 国库 / 再投资 ←──────────────────────┘
```

## 1.3 设计原则

| 类别 | 内容 |
|---|---|
| 抄（维多利亚 3 骨架） | 建造点池、建造队列、每建筑进度上限、三档建造部门（单位成本递减）、价格公式、缺料停产、私有制、破产链条、国有化 |
| 简化 | 不做人口/生活水平/利益集团/法律/科技树/基建/运输网/公司/投资池账本；市场只做全国+城市两层；商品控制在 18 种 |
| 不做 | 世界市场/贸易优势/禁运矩阵/商船/港口封锁；现金储备账本；10 年破产衰减（压缩为 30 天） |
| 时间尺度 | 全部按**天**结算（维多利亚按周） |
| 可调性 | 所有数值集中在配置表，支持游戏内 flags 覆盖，便于平衡 |

## 1.4 维多利亚 3 概念映射

| 维多利亚 3 | 本 mod |
|---|---|
| 州 / 省 | 定居点（城 / 堡 / 村） |
| 建筑等级 | 建筑数量（堆叠） |
| 生产方法（PM） | 木 / 石 / 铁 三模式（隔天生效） |

| 短缺 | 缺料 = 停产（不采用渐进惩罚） |
| 投资池 | 领主个人金钱（简化） |

# 2. 建筑系统

## 2.1 建筑组数据模型

每个定居点、每种建筑 = 一个建筑组：

```
BuildingGroup {
    string   DefId;         // 建筑定义 id
    int      Count;         // 已建数量（堆叠）
    BuildingMode Mode;      // Wood / Stone / Iron
    List<QueuedBuild> Queue;// 在建队列（每个元素 = 1 个单位）
}

QueuedBuild {
    int    Progress;        // 已投入建造点
    int    TotalWork;       // 总工时（由模式决定）
    int    Index;           // 队列位置
    bool   Paused;
}
```

- 模式对该组**全部数量**生效
- 模式切换**隔天生效**，免改造、免费用
- 建筑没有等级，只有数量堆叠（用户决策）

## 2.2 三种模式

| 模式 | 产出倍率 | 单位维护倍率 | 附加材料消耗 | 可建门槛 |
|---|---|---|---|---|
| 木制 | ×1.00 | ×1.00 | 无 | 有木制部门即可 |
| 石制 | ×1.50 | ×0.70 | 石料 | 有石制部门 |
| 铁制 | ×2.30 | ×0.45 | 石料 + 铁 | 有铁制部门 |

**规则说明**
- 附加材料消耗按建筑基准产出折算，见第 12 章数值表
- "越高级 = 效率越高、单位成本越低、吃料越高级"（用户决策）
- 缺料（任一输入商品库存不足）→ 当日**停产**，产出为 0，状态显示"缺料"
- 建筑停产不影响维护费（维护费照扣，作为压力）
- 围城 / 掠夺期间所有建筑停产；城易手后建筑保留（含模式与数量）

## 2.3 槽位与上限

| 地点 | 公式 | 上限 |
|---|---|---|
| 城镇 | 4 + 繁荣度 / 1000 | 12 |
| 城堡 | 3 + 繁荣度 / 1500 | 8 |
| 村庄 | 1 + 户数 / 500 | 5 |

- 已建 + 在建 都占槽位
- 每种建筑**不设单独数量上限**，只受槽位总上限限制
- 槽位每日结算时刷新（繁荣/户数变化会改变上限）

## 2.6 私有 / 国有

| 归属 | 可建类别 | 谁操作 | 盈亏 |
|---|---|---|---|
| 国有 | 全部 | 玩家 | 国库 |
| 私有 | 资源 / 加工 / 贸易 / 后勤 / 民生 | 领主 AI（玩家无权操作） | 领主个人金钱 |

- 军事类与行政类**只能国有**
- 玩家可**国有化**私有建筑：价格 = 造价 × 1.5（未建成按进度折算）
- 破产时经济类国有建筑**强制私有化**（见 6.4）

## 2.7 建造 / 拆除 / 取消规则

| 操作 | 规则 |
|---|---|
| 建造 | 排队 → 占槽位 → 每日投入建造点与材料 → 完成后 Count+1 |
| 拆除 | 立即，退还 50% 材料（按当前模式造价） |
| 取消在建 | 退还 50% 已投入材料，进度清零 |
| 暂停队列项 | 保留进度，不消耗建造点与材料 |
| 队列重排 | 自由上移 / 下移 |
| 队列长度 | 每定居点最多 5 项 |

## 2.8 开局预置建筑（用户决策）

接管原版村庄产出后，若村庄为空会导致全国断粮断料。开局自动预置：

| 地点 | 预置内容 |
|---|---|
| 每个村庄 | 按其特产免费预置 1 个对应资源建筑（数量 1、木制、已完成） |
| 每个村庄 | 若特产不是粮食，额外预置 1 个**农田**（数量 1、木制），保证温饱 |
| 每个城镇 | 2 个木制建造部门（已完成） |
| 每个城堡 | 1 个木制建造部门（已完成） |

预置建筑不占玩家国库，直接生成。

# 3. 建造部门与建造流程

## 3.1 建造部门

| 档 | 建造点 / 日 | 每日消耗 | 可建建筑档次 |
|---|---|---|---|
| 木制 | 5 | 木材 3 | 木档 |
| 石制 | 9 | 木材 3 + 石料 2 | 木 + 石档 |
| 铁制 | 14 | 木材 3 + 石料 2 + 铁 1 | 全部（铁档） |

- 部门本身是建筑，占槽位
- 部门可通过切换模式升级（木→石→铁，隔天生效）
- 部门可拆除（不退材料）
- **没有部门的定居点不能开工**（用户决策）
- 建造点**每城独立池**（用户决策）：本地部门只服务本地

## 3.2 建造点结算

```
城市建造点池 = Σ(本地部门数量 × 档位点数)
```

- **池子只由部门决定**；材料采购独立结算（买不到就停滞，不影响池子大小）
- 每日结算一次
- 建造点不累积（当日不用即浪费）
- 队列按顺序消耗建造点；每项每日最多投入 = 其工时 × 20%（防独占）

## 3.3 队列规则

1. 每个定居点一条队列，最多 5 项
2. 每项可上移 / 下移 / 暂停 / 取消
3. 队列项每日结算：先采购当日材料，再投入建造点
4. 材料买不到 → 当日停滞（显示"缺料"），进度不倒退
5. 从队列移除 → 进度清零，退还 50% 已投入材料

## 3.4 每日结算流程（建造部分）

```
1. 计算本地建造点池（含材料供给系数）
2. 按队列顺序遍历每一项：
   a. 计算当日需要材料 → 从本地市场买 → 不足则从全国市场调运 → 再不足则进口
   b. 材料到位 → 投入建造点（上限 = 工时 × 20%）
   c. 进度 += 投入点数 × 建造效率
   d. 进度 >= 工时 → 完成，Count+1，释放队列项
3. 刷新槽位与 UI
```

## 3.5 材料采购优先级

1. **本地城市市场**（价格最低）
2. **全国市场调运**（+10% 运费，1 天到货）
3. **进口**（+30% 溢价，2 天到货）
4. 都买不到 → 停滞

## 3.6 建造效率修正

| 来源 | 修正 |
|---|---|
| 动乱 | −20% |
| 被围城 / 掠夺 | −50% |
| 破产（30 天内） | −75% |
| 国策加成（后期） | 按国策定义 |
| 最低值 | 5% |


## 4.3 新建物品规格（3 种，代码创建）

原版基础商品是**代码创建**（`DefaultItems.RegisterAll` + `InitializeAll`），新建物品沿用同一模式，**不走 XML**：

```csharp
// 1) 新类别（贸易品类别）
var cat = Game.Current.ObjectManager.RegisterPresumedObject(new ItemCategory("fia_stone"));
```

# 5. 市场系统

## 5.1 两层结构（用户决策）

```
全国大市场（汇总视图 + 基准价 + 跨城调运中心）
  ├── 城市小市场（每城镇一个）
  │     └── 挂靠村庄（原版 Village.TradeBound，用户决策"用原版"）
  └── 城堡：无市场，挂靠原版 TradeBound 城镇
```

- 村庄产出进入其 `TradeBound` 城镇的小市场
- 城堡的产出 / 消耗也走其 `TradeBound` 城镇
- 全国大市场 = 所有城市小市场的汇总（自动聚合，无需连接建筑）

## 5.2 价格公式（照抄维多利亚）

```
市场价 = 基础价 × [1 + 0.75 × clamp((买 − 卖) / min(买, 卖), −1, +1)]
```

- 价格区间：25% ~ 175% 基础价
- 每日价格变动幅度 ≤ 10%（平滑）
- 本地价 = 全国基准价 × 本地稀缺系数
- **除零边界**：若 `min(买, 卖) = 0`：
  - 买 > 0 且 卖 = 0 → 比值取 **+1**（价格 = 175% 基础价）
  - 卖 > 0 且 买 = 0 → 比值取 **−1**（价格 = 25% 基础价）
  - 买 = 卖 = 0 → 价格 = 基础价

```
本地稀缺系数 = clamp(1 + (本地需求 − 本地供给) / max(本地需求, 本地供给, 1), 0.5, 1.5)
```

### 5.2.1 全国基准价的聚合公式（补充）

全国基准价**不是**简单平均，而是"全国统一清算价"：

```
全国买入单 = Σ(所有城市的日需求)
全国卖出单 = Σ(所有城市的日供给)
全国基准价 = 基础价 × [1 + 0.75 × clamp((全国买入单 − 全国卖出单) / min(全国买入单, 全国卖出单), −1, +1)]
```

- **只有 1 个城市生产某商品时**：全国价由该商品的全国供需决定，不自动等于该城价（该城本地价仍按本地稀缺系数计算）
- **买家看到的价格**：
  - 本地成交 → 本地价（= 全国基准价 × 本地稀缺系数）
  - 跨城调运 → 全国基准价 + 10% 运费
  - 进口 → 全国基准价 + 30% 溢价
- 全国价与本地价每日各平滑一次（变动 ≤ 10%）

## 5.3 库存与供需

每个城市小市场记录每种商品：

| 字段 | 说明 |
|---|---|
| 库存 | 当前存量 |
| 日产出 | 本地建筑产出之和 |
| 日消耗 | 本地建筑消耗 + 军队消耗 + 民生消耗 |
| 本地价 | 见 5.2 |
| 缺口 | max(0, 需求 − 供给) |

- 建筑买卖优先在本地市场成交
- 本地买不到 → 全国调运 → 进口
- **缺料 = 停产**（用户决策，不采用维多利亚的渐进惩罚）；市场面板仍显示短缺标记供玩家查看
- **粮食保底（安全阀）**：玩家国家粮食库存 < 3 天消耗时，自动从外部市场进口（溢价 +50%，可在设置里关闭）——防"什么都不建就饿死"的死局

## 5.4 跨城调运

- 触发条件：城市间价差 > 20%
- 每日容量 = Σ(本地"市场"建筑等级 × 10)
- 运费：+10%（计入买家成本）
- 到货时间：1 天
- 调运方向：价差大的优先

## 5.5 进出口

- 入口：有"贸易站"建筑的城市
- 容量 = Σ(贸易站 × 30) / 日
- 进口溢价：+30%
- 到货时间：2 天
- 关税：玩家可设 0% / 12.5% / 25%（按基础价计算），首版默认 0%

## 5.6 生活用品 → 繁荣度循环

| 商品 | 效果 |
|---|---|
| 布 / 工具 / 酒 / 陶器 | 在城市市场售出时，按销量提升定居点繁荣度 |
| 繁荣度提升 | 每 100 单位售出 → +1 繁荣度（每城每日上限 +2） |
| 过剩 | 价格下跌 → 建筑亏损（国有 = 国库承担，私有 = 领主承担） |
| 短缺 | 粮食短缺 → 繁荣度下降、忠诚下降 |

## 5.7 市场面板（图三样式）

- 入口：左侧栏按钮 + 城镇抽屉内的"市场"按钮
- 页签：商品 / 贸易
- 商品表列：图标 / 名称 / 价格 / 变化% / 供给 / 需求 / 库存 / 缺口
- 支持按价格、缺口排序
- 显示全国汇总与当前选中城市两套数据

# 6. 国库、借债与破产

## 6.1 国库定义（用户决策）

- 国库 = 玩家（国家意志）金钱
- **允许为负数 = 债务**（破产机制的前提）
- 无金库上限（用户决策）

## 6.2 收入与支出

| 收入 | 支出 |
|---|---|
| 定居点税收 | 建筑维护费 |
| 国有建筑产出出售 | 建造材料采购 |
| 关税 | 军费（军队维护） |
| 战利品 / 赔款 | 进口费用 |
| 国有化费用 | 借债利息 |

### 6.2.1 收入公式（补充）

```
【税收】
某城日税收 = (城镇繁荣度 × 0.05 + 城堡繁荣度 × 0.03 + 村庄户数 × 0.02) × (1 + 税务局加成) × 税率
税率默认 100%（可被国策/事件调整）

【国有建筑产出】
默认自动出售：产出直接按本地市场价结算成第纳尔进国库
玩家可在建筑列表切换"储备"（不进市场，留给建造/军需用）
私有建筑产出归领主，不进国库

【关税】
进口关税 = 进口货值 × 关税率（默认 0%，可设 12.5% / 25%）

【战利品】
沿用原版战斗结算，直接进国库

【示例】一个繁荣 4000 的城镇 + 3 个户数 600 的村庄：
日税收 = (4000×0.05 + 600×0.02×3) × 1.0 = 200 + 36 = 236 第纳尔/日
```

### 6.2.2 支出公式（补充）

```
建筑维护 = Σ(所有建筑单位 × 模式维护系数)   // 见 12.3
建造材料 = 队列项每日消耗（按市场价买入）
军费 = Σ(军队人数 / 100) × 50 第纳尔/日
利息 = 债务余额 × 年利率 / 365
```

## 6.3 借债与利息

- 国库 < 0 时自动进入借债状态
- 利息：基础 20% / 年（约 0.055% / 日），可被"银行"建筑与国策降低
- 利息每日结算，计入支出
- 国库 ≥ 0 时自动优先还债

## 6.4 破产（用户决策：全部惩罚都要）

**触发**：国库 < 0 持续 **7 天**

**破产惩罚（全部执行）**

| # | 惩罚 |
|---|---|
| 1 | 清空全部债务（国库归 0） |
| 2 | 取消所有在建项目（不退材料） |
| 3 | **债务下发领主**：按家族财富比例，每家族每日扣钱，直到债务还清 |
| 4 | 领主关系 −20、领主忠诚 −10 |
| 5 | 军队士气 −20（30 天衰减）、军队战斗力 −25%（30 天） |
| 6 | 全国建造效率 −75%（30 天） |
| 7 | **强制私有化**：经济类（资源/加工/贸易/后勤/民生）国有建筑转给本国领主（随机分配） |

**债务分摊公式**

```
某家族每日扣款 = 债务总额 × (该家族财富 / 全国领主总财富) × 0.02
债务总额 = 破产时国库缺口 × 2（惩罚性）
扣款持续到债务还清或家族破产（家族金钱归 0 则跳过）
```

**恢复条件**：债务还清 + 国库 ≥ 0

## 6.5 破产警告

- 国库 < 0 第 1 天起，屏幕顶部显示红色警告条："国库亏空 X 第纳尔，Y 天后破产"
- 市场面板与建筑列表顶部同样提示

# 7. 私有建筑与领主 AI

## 7.1 领主性格

每名领主开局随机分配一种性格：

| 性格 | 行为倾向 |
|---|---|
| 保守 | 只建已有建筑的补充，不尝试新类别 |
| 进取 | 偏好加工 / 工业类 |
| 军事 | 偏好军营 / 军械库 / 马厩 |
| 商贸 | 偏好市场 / 贸易站 / 驿站 |
| 懒惰 | 建造概率极低 |
| 贪婪 | 只建预估利润最高的建筑 |

## 7.2 建 / 关决策（用户决策：性格 + 盈亏）

每 7 天评估一次：

```
对每个领主：
  1. 找到其封地（定居点）
  2. 若本地槽位有空 且 领主金钱 > 建造成本 × 2：
     a. 按性格权重选择候选建筑
     b. 预估利润率 = 预估产出价值 / (维护 + 材料) 
     c. 利润率 > 性格阈值（保守 1.5 / 进取 1.2 / 军事 1.0 / 商贸 1.2 / 懒惰 3.0 / 贪婪 2.0）
     d. 通过则排队建造（使用领主个人金钱）
  3. 对已建私有建筑：
     - 连续 30 天亏损 且 性格非保守 → 拆除（退还材料归领主）
     - 连续 15 天缺料 → 切换模式（降档）
```

## 7.3 资金（补充：领主金钱的来源与结算）

**使用原版 `Hero.Gold`（已验证：`PROP Int32 Gold [get set]` + `METH ChangeHeroGold(Int32)`）。**

| 项 | 规则 |
|---|---|
| 来源 | 原版领主收入（封地税收、战利品等）照旧；本系统额外把私有建筑产出售出所得计入 `Hero.Gold` |
| 支出 | 建造费用（材料 + 人工）与维护费直接从 `Hero.Gold` 扣除（用 `ChangeHeroGold(-cost)`） |
| 与玩家国库的关系 | 完全独立；破产"债务下发领主"就是直接扣 `Hero.Gold` |
| 领主金钱不足 | 低于"建造成本 × 2"时停止新建；为负时自动关闭最亏的私有建筑 |
| 与 AI 兼容 | 只做增量扣/加，不覆盖原版领主 AI 的收支逻辑（避免破坏原版行为） |
| 玩家可读 | 建筑列表的私有建筑行显示所属领主与收益 |

## 7.4 国有化

- 玩家在建筑列表对私有建筑点击"国有化"
- 价格 = 造价 × 1.5（未建成按进度折算）
- 从国库支付给领主
- 国有化后归玩家操作

# 8. 军需与战斗力

## 8.1 军需消耗（用户决策 A+B+C）

每 100 名士兵每日消耗：

| 商品 | 数量 |
|---|---|
| 粮食 | 2 |
| 武器 | 0.4 |
| 盔甲 | 0.3 |

- **扣减规则（简化版，用户确认）**：
  1. 军队所在定居点有己方城市 → 从该城小市场扣
  2. 否则（野外 / 敌国）→ 从**全国市场统一扣**
  3. 全国也不足 → 按供给比例给部分补给，供给率下降
- 不做"最近城市搜索"（性能与边界情况都不可控）

## 8.2 供给率

```
粮食供给率 = min(1, 实际供应 / 需要)
武器供给率 = min(1, 实际供应 / 需要)
盔甲供给率 = min(1, 实际供应 / 需要)
总供给率 = min(三者)
```

## 8.3 作用 A：自动结算

```
自动结算战斗力系数 = 0.75 + 0.5 × 供给率
（供给 0% → ×0.75；供给 100% → ×1.25）
```

作用于大地图自动战斗（`MapEvent` 结算）。

## 8.4 作用 B：手动战斗（用户确认的推荐方案）

- 战斗开始时（`Mission` 初始化），对玩家一方所有士兵应用：

```
攻击倍率 = 0.90 + 0.20 × 供给率
护甲倍率 = 0.90 + 0.20 × 供给率
```

- **实现方式（已验证 API）**：
  - 挂点：自定义 `MissionBehavior` 重写 `OnAgentBuild(Agent agent, Banner banner)`（`MissionBehavior` 公开虚方法）
  - 取属性：`agent.AgentDrivenProperties`（`Agent` 上有 `PROP AgentDrivenProperties [get set]`）
  - 攻击加成：`AgentDrivenProperties.DamageMultiplierBonus`（+0.2 = +20%）
  - 护甲加成：按倍率缩放 `ArmorHead` / `ArmorTorso` / `ArmorLegs` / `ArmorArms`
  - 速度加成：`MaxSpeedMultiplier` / `CombatMaxSpeedMultiplier`
  - 改完后调用 `agent.UpdateCustomDrivenProperties()` 生效
- 敌军（AI 国家）同样按各自的供给率计算
- 战斗内 UI 不显示具体数值（保持沉浸）

## 8.5 作用 C：士气 / 补给 / 行军

| 项 | 公式 |
|---|---|
| 士气 | + (供给率 − 0.5) × 10 |
| 行军速度 | × (0.90 + 0.20 × 供给率) |
| 补给消耗 | 供给率 < 50% 时，军队每日损失 1% 兵力（逃兵） |

# 9. AI 国家

## 9.1 市场自动平衡

每 7 天：

1. 扫描本国各城市市场缺口
2. 缺料建筑 → 切换更低模式（降档保产）
3. 过剩商品 → 切换更高模式（提效）
4. 严重缺口 → 进口
5. 过剩 → 出口

## 9.2 自动建造

每 7 天：

1. 按缺口权重生成候选（粮食缺口 > 军需缺口 > 建造材料缺口 > 民生）
2. 检查国库（AI 国家的国库 = 其统治者金钱）
3. 国库不足 → 减速（跳过本轮）
4. 建造使用其自身建造部门与建造点

## 9.3 安全阀（防崩）

- 价格带宽限制在 25%~175%（公式天然保证）
- 粮食保底：AI 国家每城至少 1 个农田（不足时优先补）
- AI 破产简化：不执行强制私有化，只减速 30 天

**三档性价比核算（以农田为例，日收益 = 产出价值 − 维护 − 附加材料价值）**

| 模式 | 产出 | 产出价值 | 维护 | 附加材料 | 附加价值 | 日净收益 | **建设材料** | **材料价值** | **回收期** |

| 木制 | 粮 4 | 52 | 2.0 | — | 0 | +50.0 | 木 20 | 500 | **10 天** |

| 铁制 | 粮 9.2 | 119.6 | 0.9 | 石 1 + 铁 0.6 | 18 + 36 | +64.7 | 木 40 + 石 30 + 铁 20 | 2740 | **42 天** |

**结论与修正**
- 三档日净收益递增（50 → 58.6 → 64.7），但**回收期成倍拉长**（10 → 19 → 42 天）：**铁档是长线投资，不是中期选择**
- 若战争节奏是"每 10~20 天一场"，铁档短期内不回本 —— 定位是"后期全国铁制化"，中期应以石档为主
- 铁档的约束来自**回收期 + 铁/煤供应链**（0.6 铁/日/单位，10 个农田就是 6 铁/日）与**部门门槛**，不靠维护费
- 若实测发现铁档仍过强，优先调整**附加材料系数**（如铁档石料 1 → 2、铁 0.6 → 1.5），而不是改维护费（维护费是用户定的"越高级越低"）

## 12.9 民用消耗（含单位口径说明）

> **单位口径（重要）**：本 mod 的粮食单位与原版**不同量级**，一律**按本表为准**。
> 原版城镇：`繁荣度 / 40`（4000 繁荣 = 100 粮/日）、驻军 `/20`、库存上限 300（已验证 `DefaultSettlementFoodModel`）。
> 本 mod：`繁荣度 / 1000`（4000 繁荣 = 4 粮/日）——为与建筑产出（木档农田 4/日）自洽而重定标。
> 因此**城镇食物结算必须由本系统接管**（见 13.5），否则原版消耗量级会把我们的产出瞬间吃光。

| 项 | 公式 |
|---|---|
| 城市粮食消耗 | 繁荣度 / 1000 / 日（繁荣 4000 → 4/日） |
| 村庄粮食消耗 | 0（自给自足） |
| 城市生活用品消耗 | 布 / 酒 / 陶器：繁荣度 / 2000 / 日（驱动 5.6 繁荣度循环） |
| 军队随身口粮 | **沿用原版**（士兵背包食物，`MobilePartyFoodConsumptionModel` 不动） |
| 军需粮食 | 本系统额外征收的**国家后勤补给**（见 8.1），与随身口粮不冲突、不重复 |

**示例（50 村 + 10 城 + 5000 兵）**：
```
粮食产出 = 50 村 × 4 = 200/日（预置农田）
粮食消耗 = 10 城 × 4 + 5000 兵 × 0.02 = 40 + 100 = 140/日
           （其中 5000 兵 × 0.02 = 8.1 的"每 100 兵 2 粮/日"）
结余 = +60/日（无战争时安全；一场大战或几个村被占就会转负）
```

## 13.2 接管原版村庄产出（已验证挂点）

1. **挂点**：`VillageProductionCalculatorModel`（接口）的三个方法：
   - `CalculateDailyProductionAmount(Village village, ItemObject item)`
   - `CalculateDailyFoodProductionAmount(Village village)`
   - `CalculateProductionSpeedOfItemCategory(ItemCategory item)`
2. Harmony **前缀**：玩家国家所属村庄 → 返回 0（或跳过原版计算）
3. 产出改由本系统结算（预置建筑 + 玩家建筑）
4. 若前缀在某些调用路径上不生效，备选挂点：`VillageGoodProductionCampaignBehavior.TickGoodProduction(Village, bool)` / `TickFoodProduction(Village, bool)`（nonpublic）
5. **前缀必须带归属判断（防误伤 AI 国家）**：

```csharp
// 前缀逻辑（示意）
if (village.OwnerClan != null
    && village.OwnerClan.Kingdom != null            // 防双方都为 null 时误判
    && Clan.PlayerClan != null
    && Clan.PlayerClan.Kingdom != null              // 玩家未立国时不接管
    && village.OwnerClan.Kingdom == Clan.PlayerClan.Kingdom)
{
    return false;   // 玩家国家：接管，产出由本系统结算
}
return true;        // 其他（含 AI 国家、玩家未立国）：保留原版产出
```

6. 首版 AI 国家保留原版产出（减少变量）；后续可同样接管

## 13.5 城镇食物接管（已验证）

**原因**：原版城镇食物消耗是 `繁荣度 / 40`（4000 繁荣 = 100 粮/日，已验证 `DefaultSettlementFoodModel`），是本 mod 量级（`/1000`）的 25 倍。若只接管村庄产出而不动城镇消耗，城镇会瞬间饿死。

**方案（二选一，优先 A）**：

```
A. 改比率（最小改动，推荐）
   Harmony Postfix：DefaultSettlementFoodModel.get_NumberOfProsperityToEatOneFood
   → 返回值 40 改为 1000
   效果：所有城镇（含 AI）按本 mod 量级消耗，公式与 UI 全部沿用原版

B. 改计算（备用）
   Harmony Postfix：DefaultSettlementFoodModel.CalculateTownFoodStocksChange(Town, bool, bool)
   → 把食物变化重算为我们的公式
```

- 相关 API（已验证）：`SettlementFoodModel.FoodStocksUpperLimit`（300）、`NumberOfProsperityToEatOneFood`（40）、`NumberOfMenOnGarrisonToEatOneFood`（20）、`CalculateTownFoodStocksChange(Town, bool, bool)`
- 军队随身口粮（`MobilePartyFoodConsumptionModel`）**不动**；军需粮食是本系统另加的国家后勤层（12.9）

# 16. 玩家体验节奏与失败案例

## 16.1 玩家体验节奏

> **时间尺度**：按原版 1x 速度，**1 游戏日 ≈ 1 分钟现实时间**（暂停 / 战斗 / 加速会浮动），即 1 小时现实 ≈ 30~60 游戏日。
> 12.8 的回收期单位是**游戏日**：铁档 42 游戏日 ≈ 现实 1 小时左右。

| 阶段 | 时间 | 玩家在做什么 | 系统在推动什么 |
|---|---|---|---|
| 开局 | 第 1 小时 | 熟悉地图指挥、看预置建筑、建第一个农田 / 伐木场、补建造部门 | 温饱压力：粮食日消耗、市场价波动 |
| 早期 | 1~10 小时 | 补资源建筑、铺建造部门、切石制模式、开第二产业 | 材料瓶颈：石料 / 铁开始短缺，价格拉高 |
| 中期 | 10~30 小时 | 建炼铁厂 / 工具作坊 / 武器作坊、管市场平衡、切铁制模式 | 军需压力：战争消耗粮食 / 武器 / 盔甲 |
| 后期 | 30 小时+ | 全国铁制化、出口过剩品、国有化私有建筑、破产管理 | 规模压力：维护费、债务、AI 竞争 |

**阶段提示**（右下角信息栏 / 建筑列表顶部）：

| 条件 | 提示 |
|---|---|
| 粮食库存 < 3 天消耗 | "缺粮" |
| 建造点有剩余但队列空 | "建造点浪费" |
| 国库连续 3 天负增长 | "财政赤字" |
| 军需供给率 < 80% | "军需不足" |

## 16.2 失败案例（安全阀验证）

| 场景 | 30 天后结果 | 系统应对 |
|---|---|---|
| 玩家什么都不建 | 无战争时勉强维持温饱（预置农田刚够军粮 + 民用），**没有抗风险能力**；战争 / 被围城 / 粮食村被占 → 立刻缺粮 | 预置农田保底 + 粮食保底进口（见 5.3）；仍会因战争陷入困境（这是设计意图：逼迫玩家扩产） |
| 玩家只建军事不建经济 | 军需断供 → 士气 / 战斗力下降、逃兵 | 军需系统自然惩罚 |
| 玩家疯狂建造导致破产 | 破产全流程触发：清债、领主扣钱、强制私有化 | 破产系统接管 |
| AI 国家粮食崩了 | AI 自动降档 + 进口 + 粮食保底 | 9.3 安全阀 |
| 玩家全切铁档但没铁 | 全部缺料停产，产出归零 | 玩家自己承担；市场面板显示缺口 |
| 一个城被反复围城 | 建筑停产但保留；城易手后归新主人 | 2.2 规则 |

## 17.2 API 验证结果（原开放项，已全部确认）

| # | 项 | 结论 |
|---|---|---|
| 1 | 新物品注册方式 | **不是 XML**：原版基础商品为代码创建（`DefaultItems`）；新建物品同样用代码（`ItemObject.InitializeTradeGood` + `ItemCategory.InitializeObject` + `RegisterPresumedObject`）。见 4.3 |
| 2 | 村庄产出入口 | `VillageProductionCalculatorModel.CalculateDailyProductionAmount` / `CalculateDailyFoodProductionAmount`（接口，可 patch）；备选 `VillageGoodProductionCampaignBehavior.TickGoodProduction` / `TickFoodProduction`。见 13.2 |
| 3 | 战斗加成 API | `Agent.AgentDrivenProperties` 的 `DamageMultiplierBonus`（攻击）/ `ArmorHead·Torso·Legs·Arms`（护甲）/ `MaxSpeedMultiplier`（速度）；挂点 `MissionBehavior.OnAgentBuild`；改完调 `UpdateCustomDrivenProperties()`。**原文档写的 `AttackDamageMultiplier` / `ArmorEffectiveness` 不存在，已修正** |
| 4 | 自动结算入口 | `CombatSimulationModel.GetBattleAdvantage(MapEvent, out ExplainedNumber defender, out ExplainedNumber attacker)`（接口参数顺序已确认：**defender 在前**）。**证据**：apidump `type` 读取 `TaleWorlds.CampaignSystem.dll` 的 `CombatSimulationModel` 接口，输出为 `METH ABSTRACT virtual Void GetBattleAdvantage(MapEvent mapEvent, ExplainedNumber& defenderAdvantage, ExplainedNumber& attackerAdvantage)`。**P7 实现时仍需 dump 一次实际调用**，确认 out 顺序与"游戏确实读取该值"（`ExplainedNumber` 是 struct，需确认加成生效路径） |
| 5 | 地图徽标投影 | 复用现有名牌投影方案（`MBWindowManager.WorldToScreenInsideUsableArea`），性能按 < 100 个评估 |
| 6 | 相机飘移 | 复用 `NationalWillCamera` / `RequestCameraGoTo`（RTS 桥已验证可用） |
| 7 | 领主金钱 | `Hero.Gold` + `Hero.ChangeHeroGold(Int32)`（已验证） |
| 8 | 城镇税收 | `Town.TradeTaxAccumulated`（可读） |

> 结论：**设计文档中的 API 引用已全部验证，无未确认项。**
